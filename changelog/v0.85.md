## v0.85.0 (2026-10-20)

### feat(engine): wireAgentBuilder 统一组装 + 压缩连续性根因修复

**问题一（组装分叉）**：`config-bridge.buildAgent` 与 `gateway.buildAgent` 各维护一套「配置 → AgentBuilder」接线。Gateway 路径漏接 `withModelLevels` / `summarize` / `contextEngine`——子系统 `think.model:'mini'` 解析成字面量 `"mini"` 发给 API（日志 `model=mini` 秒失败；真 `mimo-v2.6-flash` 全成功），且 `octopi.json` 的 `contextEngine.*`（含 `proactiveCompactRatio`）在 `octopi serve` 下被静默忽略。

**问题二（压缩连续性）**：超长 turn 触发主动压缩后任务持续性丢失。根因链：middle 含当前 run 工作记录 → `preprocessToolResults` 先打码再摘要（自残输入）→ 占位符 `Use the tool again` 诱导重做 → `fallbackTruncate` 只留 4 条 → 重启/配置 `proactiveCompactRatio:0` 后粘滞视图被打回全量（请求 prefix 变化 = 冷 prefill 撞 300s 超时，用户体感「挂死」）。

**修正**：

- **`wireAgentBuilder` 唯一组装出口**（`harness/agent/wire-agent-builder.ts`）：模型档 / summarize / contextEngine / security+riskPolicy / budget / runGuard / persona / skills / memory stores / subsystems / toolIsolation / effectPolicy 全部收口。`config-bridge` / `gateway` / `createAgent` 只调用它；宿主适配（circuit breaker、WS、approval、Knowledge）留在 Gateway。**无兼容双轨**。
- **`toGatewayConfig` 透传** `contextEngine` / `runGuard` / `security`；`resolveContextEngine` 缺 `type` 落默认引擎（只配旋钮不再抛错）。
- **压缩视图粘滞**：已有 `previousSummary` / `lastProactiveMessageCount` 后不因估算回落或 `ratio=0` 打回全量；`ratio=0` 只禁**新** LLM 压缩。粘滞重建保留 `lastProactiveMessageCount` 之后的增量（超预算机械收束，禁止 `head+旧摘要+tail` 吃掉中间新内容）。
- **方案 E**：`isMidTurn`（最近真实 user 之后已有工具活动）→ 禁止 LLM 摘要，只走机械分级；turn 边界才允许语义压缩——保护当前 run 活动工作记录。
- **F-a/b/c/d**：占位符归档措辞（禁诱导重跑）、`error` 永不打码、LLM 摘要吃**原文**（机械打码只作用于丢弃体）、`fallbackTruncate`/overflow 降级 = 工具调用账本 + 近尾（禁止只留 4 条）、摘要模板 HANDOFF + Done 必含产物路径。
- **引擎注入打标**：reliability wrap-up/steer/noop/truncate notice 统一 `metadata.source:'engineHint'`（入 `ENGINE_CARRIER_SOURCES`）；`isMidTurn`/老化边界只认 source，不认文案格式。

**独立评审**（fresh-eyes 子代理）：P0 粘滞丢增量 + P1 `isMidTurn`/`[System:]`/RunGuard 多绑/createAgent 静默 SQLite/`n≤6` 假通知——5 条 must-fix 已修；P2 假测试/`as never`/skill 双路径/dead branch/isMidTurn 契约——6 条已修。根因原则复审：`[System:` 前缀过滤改回「注入点打 source」。

**验证**：wire 契约（spy 锁接线 + summarize 真实 model id）、compact-sticky（粘滞/增量/`engineHint`/空丢弃/error 保真）全绿；全量 2865+ passed；tsc/lint/三包 build 干净。既有 2～3 个无关 flaky（file-release 路径 / file-watch / knowledge 排队）不变。
