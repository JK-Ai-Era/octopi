## v0.96.1 (2026-10-29)

### fix(reliability): turn 信封收尾——turnSeq 分配即持久化 + 闭标幂等收养（中断续跑不再中止会话）

- **根因链**（2026-10-28 事故）：run 中断（事件循环冻结/被杀）时 `turnSeq` 计数器只随收尾 save 落盘而丢失 → 续跑复用已闭 turn 的 id → `ensurePreviousTurnClosed` 为上一信封补写闭标 → 收尾 `appendTurnEnd` 撞全局 write-once throw → **loop 已 completed 的 run 被升级成 error（会话被中止）**；抛错又发生在 save 之前，计数器继续丢失、bug 自我延续（同会话三次续跑同用 t1）。
- 修复：(1) `persistTurnSeq` 计数器分配即落盘（缺 `updateMetadata` 的 store 由收尾 save 兜底，失败留痕不中断）；(2) `appendTurnEnd` 改按**信封区间**幂等收养——turn_end 是状态标记（turn 已闭）而非事件，同 id 的历史闭标属上一个信封、不挡本信封闭合；(3) 计数器读取补 `Number.isFinite` 守卫（防 `'tNaN'` 静默复用）。
- **breaking**：`appendTurnEnd` 不再抛 `turn_end already exists`。该 throw 正是本次事故的伤害来源；已全仓核实无消费方依赖其存在或文案。
- 不变式随之修订：「每 turn_start.id ⟺ 恰一条 turn_end.id」→「**每个信封**恰一枚闭标；id 在崩溃续跑遗留数据里可能重复」（turn-envelope.ts 契约注释同步）。

### fix(storage): JsonlSessionStore.updateMetadata 不再静默清掉 contextDetachIndex

- `save()` 写 state 含 `contextDetachIndex`，`updateMetadata()` 的重写字段表却漏了它——仅因写一次 metadata 就把租约截断点抹成 0，续跑时全量历史灌进 LLM 窗口（超窗/费用失控）。此前仅 abortedTurn/lastStop 清理偶发触发；本次把计数器写入放进 run 启动热路径后变为每 run 必发，被独立评审拦截。补「updateMetadata 后 state 字段与 save 一致」回归测试；`primaryAgentId` 回退语义与 save 对齐。

### feat(observability): 事件循环停滞看门狗 + wire dump 响应留痕

- **loop-watchdog**（2026-10-28 冻结事故的自检器官）：worker 线程心跳监测主循环——主循环冻结（accept/timer/handler 全停）时 worker 仍存活，静默超阈值即写 `logs/loop-watchdog.jsonl` 报告并（macOS）自动 `sample` 抓阻塞栈。本次事故 4.5h 冻结因无栈样致阻塞点永久失考；此后同类事件自带停滞起点与栈。开关与阈值经 `observability.loopWatchdog` 配置（有合法长同步作业的部署应放宽 `stallThresholdMs`）；观测 fail-open、worker unref 不阻止退出。
- **wire dump 响应留痕**：`index.jsonl` result 行新增 `response`（正文/推理/finishReason，按 `observability.llmRequestDump.maxResponseChars` 截断）。内容过滤拒答以 **200 内联**返回（reasoning 照常、正文被替换成罐头拒答），此前错误面完全不可见、「为什么被判 high risk」无从定位。chat/stream 同一对称形态：空正文不落字段、done 携带全文仅在无 content 增量时采用（防重复）。
- 验证：全量 3562 passed / 2 failed（两例为 handover 批既知未完项，与基线一致，零新增失败）；新增回归用例 12 个；经独立对抗性评审（1 blocking + 13 minor 全部处理，blocking 为上述 storage 修复）。

## v0.96.0 (2026-10-28)

### feat(context): 交接式摘要——同形前缀 + 输出闸门 + 诚实失败语义

- **定位改「会话交接」**（拍板：中段摘要的本质是把之前会话做的事说清楚、交接给后续对话，而非中段压缩编码）。摘要产出四段式交接书：①goal+状态 ②未决项与承诺 ③结论与拍板(含理由) ④证据指针。
- **摘要请求 = 会话同形前缀 + 尾部交接指令**：llmPrefix 的 system 字节取自会话托管 system 消息（与真实请求逐字同源，缓存命中前提）；走**当前会话模型**（gateway 显式绑定 `bound.modelName`，缓存 per provider+model）；**无便宜档回落**（小模型窗口吃不下输入=换一种失控）。task 快照随指令尾部注入（B0：易变块不进 system）；指令含折叠区间边界（替换到第几条、尾部保留勿总结）。
- **输出闸门**：对话体/工具调用形状 + 结构性回声判据（命中输入行 ≥3 或复读占输出 ≥60%，回声源=模型实际看到的文本投影）判污染 → 加严指令重试一次 → 仍污染按摘要失败降级，**坏摘要不落盘**（修根此前「摘要=原文续写」的事故形态）。
- **失败语义（fresh 判定）**：无新语义摘要时不推进覆盖点/增长门/冷却（宁可胖不丢），`compacted:false` + `reason:summarize_failed:*` 如实透传；`[Coverage]` 覆盖行改装配时按覆盖点动态渲染，不再烘进摘要正文（不累积、不回喂）。
- **窗口护栏**：摘要硬顶 = min(4×软目标, maxOutputTokens, 0.1×窗口, 窗口−输入)；前缀放不下回退文本化中段旁路（如实 cache-miss），仍放不下显式 `window_exhausted` 失败。软目标预算 clamp(2%, 2k, 8k)（P1c），`contextEngine.summaryBudget` 可配 ratio/min/max。
- proactive/overflow 摘要路径接入**同一输出闸门**（污染 → 截断降级）。

### fix(context): 手动结构压缩 slice(-0) 零保护视图陷阱与报数口径

- `protectTail=0` 时 `slice(-0)` 返回全量数组，四条路径在「零保护」参数下把全量当中段残留——手动压缩报数虚高（「559.2k → 535.8k」的 after 是中段原文重复计数）。修复后零保护即零保留；text 路径补 `too_short` 守卫。
- 报数口径 = 装配同源（`stickyViewMessages` 共享，度量=装配）；无语义摘要/失败不虚报（回退 `tokensBefore`）；不再写 `lastEstimatedTokens`（校准基只允许「实际请求」口径）。
- 修复压缩后「覆盖点→尾部保护区」增量在回放视图静默消失（stickyViewMessages 增量位，宁可胖）。

### fix(context): 收尾杂项

- 能力级 compact 默认保护值与引擎同源（头 3→5）；`summarySoftTargetTokens`/`detectSummaryContamination` 自能力门面导出；conversation_default 抽取策略与四段式同构；`octopi.example.json` 补 `summaryBudget` 模板。

**破坏性说明**：摘要输出改四段式交接书（旧「中段摘要」单段格式不再产出）；粘性视图头部保护默认 3→5（默认视图=首 5 + 摘要 + 尾 20）；压缩失败不再被上报为成功（此前 `compacted:true` + 假报数）。

**已知遗留**：proactive 路径（LLMSummaryCompressor）仍用 Done/ToDo HANDOFF 模板，与四段式并存待统一；压缩旁路（cache-miss 回退）可观测性未暴露。
