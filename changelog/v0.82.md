## v0.82.6 (2026-10-17)

### fix(web): separate reasoning from chat content, page session history, and tidy tool display

**问题**：v0.82.4 把 `delta.reasoning_content` / `thinking_delta` 映射成 `type: 'content'`，思考过程被拼进 assistant 正文并推到 WebUI，回放里也变成「内心戏 + 答复」缝合怪。会话打开只拉 `limit: 100` 的**前** 100 条，长会话（实测 365 条）直接丢 2/3 记录；有 toolCalls 的空正文 assistant 被整条 `continue`，工具轮次在聊天流里消失。工具 `purpose` 未落入 `ToolResult`，历史回放从不存在的 `tr.args` 抠 purpose 恒为空；助手气泡还冗余显示「工具: id」。左侧历史会话列表因 `.app-main` 网格行高被内容撑开而无法滚动。

**修正**：
- **reasoning 通道**：`LLMStreamChunk` 增加 `type: 'reasoning'`；provider 输出 thinking 增量为 reasoning chunk；`call-model` 只喂 watchdog + 发 `llm_thinking_delta`，不拼进 `LLMResponse.content`；thinking 落 `message.metadata.reasoning` 供回放折叠展示
- **历史分页**：`getSessionMessages` 支持 `direction=backward`（cursor=exclusive end）；打开会话取末尾 100 条，滚动临近顶部再向前拼页；**仅 UI 展示**，续聊仍走服务端完整 Discourse 装配
- **气泡规则**：无正文且无思考/错误的 assistant 不渲染气泡，只留工具卡片；有正文/思考/错误才出气泡，且不再在气泡内重复「工具: …」
- **purpose 贯通**：`ToolResult.purpose` 落盘（`result.purpose` 或 `toolCall.arguments.purpose`）；历史优先读 `toolResults.purpose`，再按 `toolCallId` 从 assistant `toolCalls.arguments` 回填
- **侧栏滚动**：`.app-main` 锁 `grid-template-rows: minmax(0, 1fr)`，会话列表独立滚动，展开/收起按钮移出滚动区

**测试**：`tests/reasoning-channel.test.ts`（2）— call-model 思考/正文分流与 empty_stream fallback；`tests/conversation-adapter.test.ts`（+2）— llm_thinking_delta、metadata.reasoning、tool purpose 映射；`tests/provider-reasoning-passthrough.test.ts`（5）— 改为期望 `type: 'reasoning'`。build + lint 绿；全量 2798 过（3 个既有无关红不变）。

## v0.82.5 (2026-10-17)

### fix(tools): harden undo journal against external sweeps and make file/git tools EOL-aware

**问题**：开发中反复出现 file_write/file_edit 集体 `ENOENT ... undo/blobs/<hash>`，整个 turn 文件写入全挂。探针复现实锤根因链：gateway 测试 `afterEach → Gateway.stop()` 的"进程退出收残留 undo"清扫打到真实 `~/.octopi/sessions`（测试未隔离 OCTOPI_HOME），且清扫者无法区分崩溃残留与他人进程正在用的活 undo；`TurnFileUndoLog.storeBlob` 又无自愈，目录被外人删掉后 journal 故障连坐业务写入。另有一类反复出现的行尾问题：file_edit 多行 old_text（`\n` 书写）在 CRLF 文件上静默匹配失败、插入 LF 造成混杂行尾；git 工具安全隔离使 autocrlf 不可见，CRLF 原样入库产生整文件 churn（shell git 预览干净、提交却翻转）。

**修正**：

- **测试隔离**：vitest setup 每个测试文件独立临时 `OCTOPI_HOME`（tests/setup/isolate-octopi-home.ts），测试不再触碰真实运行时目录
- **undo 所有权**：`TurnFileUndoLog.begin()` 写 `owner.json`（pid）；`resolveSessionUndoOnClose` 增加 `skipLiveForeign`，`Gateway.stop()` 清扫跳过他人活跃进程的 undo（死进程 / 本进程残留照常收）
- **storeBlob 自愈**：blobs 目录被外部删掉时重建重试一次，业务写不再被 journal 故障连坐
- **file 工具行尾感知**（tools/eol.ts）：file_edit 匹配自动换算行尾候选项（消灭多行匹配静默失败），插入文本换算成文件主导行尾；file_write 覆写/追加已有文件保留其主导行尾，新建文件保持原样
- **git_commit EOL 归一**：提交前把已暂存文本文件规整到其 HEAD blob 的行尾约定（新文件 / 删除 / 二进制 / 非 UTF-8 不动），`eol: 'keep'` 可关闭；结果返回 `eolNormalized` 清单

**测试**：`tests/undo-eol-hardening.test.ts`（7）— storeBlob 自愈、owner/skipLiveForeign、file_edit/file_write 行尾、git_commit 归一与 keep；全量 283 绿（既有无关红：domains-catalog `session/schedules` 未登记）。

## v0.82.4 (2026-10-16)

### fix(loop): stop model-call idle watchdog tripping on long silent thinking

**问题**：复杂任务频繁出现 `Stream fallback to sync (Model call idle timeout: no data received from provider within timeout window)`。引擎模型调用看门狗的空闲窗口默认仅 120s（absolute 300s），而复杂任务的大上下文 prefill 与 reasoning 模型长思考会产生超过 120s 的流式静默期（含首 token 等待），一超即放弃流式回退同步。叠加两个触发源：provider 层把 `delta.reasoning_content`（MiMo / DeepSeek 系 OpenAI 兼容字段）与 Anthropic `thinking_delta` 静默丢弃，思考流对看门狗完全不可见；且 `modelCallIdleTimeoutMs` 在 gateway-config 仅声明未消费，octopi.json 无法调参，120s 实际写死。

**修正**：

- 默认超时上调为 idle 300s / absolute 900s，导出 `DEFAULT_MODEL_CALL_IDLE_TIMEOUT_MS` / `DEFAULT_MODEL_CALL_ABSOLUTE_TIMEOUT_MS`（core/loop/agent-loop）
- 新增 `modelCall` 配置段（`idleTimeoutMs` / `absoluteTimeoutMs`）贯通全链：octopi.json（Zod schema + example）→ `toGatewayConfig`（GatewayConfig 补 `modelCallAbsoluteTimeoutMs`）→ `AgentBuilder.modelCallTimeouts()` → Agent loop config；serve 与 config-bridge 两条构建路径同接
- OpenAI 兼容 provider 补 `delta.reasoning_content` 透传；Anthropic provider 对称补 `thinking_delta` 透传（与既有 `delta.reasoning` 同语义：思考增量进 content，喂饱 watchdog 且不再隐藏思考过程）
- `octopi.schema.json` 经 `npm run build` 重新生成

**测试**：`tests/model-call-timeouts.test.ts`（7）— 默认值、schema 校验、toGatewayConfig 映射、Agent options 透传；`tests/provider-reasoning-passthrough.test.ts`（5）— reasoning_content / reasoning / thinking_delta 透传；lint 与全量回归绿。

## v0.82.3 (2026-10-16)

### fix(config): pass effectPolicy through toGatewayConfig

**问题**：`octopi serve` 的配置装配 `toGatewayConfig()`（src/config.ts）静默丢弃 `effectPolicy`——`resolvedAgents` 映射没有拷贝 `agents[].effectPolicy`（`AgentDefinition` 类型也缺该字段），顶层 `effectPolicy` 也没进 `GatewayConfig`。于是 gateway.buildAgent 的 `agent.effectPolicy ?? config.effectPolicy` 拿到 `undefined`，runner 回落引擎缺省 `DEFAULT_EFFECT_RUN_MODE = 'workspace'`：配置写的 `mode: "project"` / `transactionRoots` 全部不生效（Runtime banner 停在 `Effect mode: workspace`，shell 被 `shellEscape=deny` 拒绝）。config-bridge（嵌入路径）本就透传，唯 serve 装配断链。
**修正**：`AgentDefinition` 增加可选 `effectPolicy` 字段；`toGatewayConfig` 在 agent 级与顶层两级透传（agents[] 覆盖顶层，与 gateway.buildAgent / getSessionEffectRoots / resolveSessionUndoOnClose 消费口径一致）。补回归测试 `tests/config-gateway-effect-policy.test.ts`（3 例）。

## v0.82.0 (2026-10-16)

### feat(context): root AGENTS.md / CLAUDE.md as scoped runtime instructions

**问题**：多 root 场景下，各项目目录里的 AGENTS.md / CLAUDE.md（工作方式约定）进不了 system prompt；Runtime 只列了 Allowed roots，模型不知道该目录下的本地规范。
**拍板**：挂在 Runtime 层 workspace/roots 块之后（`root_instructions`），不新开 ContextLayer——这是 run 级、随 cwd/allowRoots 变化的活态信息；agent 自身的 `agents/<id>/AGENTS.md` 仍属 Persona，两者不混。

**格式**（块开头含作用域与优先级说明）：
```
<root_instructions>
Scope: each block applies ONLY to the root path named in its root attribute. …
Priority: system rules and the agent persona take precedence. …

<instruction_block root="/ws/project" source="AGENTS.md">
…原文…
</instruction_block>
</root_instructions>
```

**行为**：
- 只读 root 目录这一层的 AGENTS.md / CLAUDE.md（不递归）；同 root 两份都在时 AGENTS 在前、CLAUDE 追加
- 多 root 各自成块，`root` 属性区分作用域；cwd 所属 root 排最前（`isPathInside`，win32 大小写归一）
- 单文件 16KB / 合计 48KB：首份可截到合计上限，其后装不下的整份跳过（继续尝试更小的后续文件）
- 正文结束标签中和（防恶意仓库逃逸出 instruction_block）；截断提示中的 path 走 XML 转义
- 指纹缓存（mtimeMs:size + maxBytes），换上限或文件改写后不吐陈旧内容

**接线**：`harness/context/root-instructions.ts`（新）→ `withRuntimeEnvironmentInjection` 增 `rootInstructions` → `SessionAwareRunner` 每 turn 加载并注入。
**测试**：`tests/harness/runtime-root-instructions.test.ts`（23：作用域标签、双文件顺序、cwd 排序、大小写、逃逸、截断/预算、缓存失效）。
