## v0.107.3 (2026-11-11)

### fix(gateway): run-instance security guard rebuild + child wire-dump provenance

- **securityIntegrity 跨进程守卫（TypeError 事故修复）**：P0b 把 `securityIntegrity` 活对象 JSON 进 boot，方法被剥成 `{fingerprint}` 残壳，子进程 run 起点 `recheck()` 抛 `recheck is not a function`（run 全数 error 终止）。修复按「boot 纯数据纪律」：`RemoteRunBackend.start` 显式剥离活守卫（配 `configPath` 缺失即拒启动，不静默丢闸）；run-serve-child 按 `configPath` 重建守卫，与 gateway 各自持锚（service-topology §7.3）。console 受控写重锚定经新增 `reattestSecurity` control op 同步子进程；同步失败降级 warning（子进程保持漂移拒新 run，fail-closed）。
- **wire dump 留痕（OP-TOOL-1 后续）**：P0b 子进程 `createProviderFromConfig` 漏传 `wireDump`，run 全走子进程后 LLM 请求/响应零留痕（事故复现时无响应体可查的直接原因）。修复：run-serve-child 按 `observability.llmRequestDump` 建 sink 并注入 provider 工厂。
- **协议硬化**：run-host 未知 control op 返回明确错误（不再静默 fall-through），为多版本混跑的 op 演进兜底。
- **验证**：`tests/run-remote-backend.test.ts` 新增 3 个回归锚（boot 剥守卫 + configPath 自建 e2e、无 configPath 拒启动、wire dump 留痕），全绿；网关重启后线上收发正常。
- **P0c 注记**：跨版本缺口（旧版 run-serve-child 不按 configPath 建守卫 → 多版本拉起时漂移闸 fail-open）已登记 `arch/service-topology-p0c.md` §4.3/§4.6，健康门须核查 `securityGuard: armed|absent`。

## v0.107.2 (2026-11-11)

### fix(core/engine): OP-TOOL-1 — elision vocabulary namespaced + degraded tool args rejected at dispatch

Context-aging degradation markers (`…[N chars]` etc.) were leaking into **live
tool-call arguments** and being executed silently (placeholders written into
files, used as git commit messages, run as shell commands). Mechanism
adjudication (engine rewrite vs model-copied output) stays open — see `feat`
below for the evidence capture that settles the next occurrence — but the fix
does not depend on it:

- **New `core/elision.ts`** — single source for degradation-marker vocabulary
  (generation + detection): markers are now namespaced `[octopi:elided N chars]`
  / `[octopi:elided +N chars]` / `[octopi:truncated]`, unmistakable as content
  and non-copyable by accident. Old forms (`…[N chars]`, `…[truncated]`,
  `…[preview omitted]`, `[... truncated]`, …) stay detectable for polluted
  history.
- **Dispatch-boundary guard** — `agent-loop.prepareToolCall` rejects any call
  whose arguments contain degradation markers (whole-value / marker-suffixed /
  prefix carriers / `_aged` fallback objects) with a fail-loud error that guides
  the model to re-derive the value from source. One choke point covers every
  tool; per-tool patching is not needed.
- **All in-repo producers migrated to the vocabulary** (tool-result-aging args +
  pointer, file-search preview/truncation, tool-validator result caps,
  memory-steward evidence splices, gateway client-tool html summary). Detector
  regexes for the result-side notice families (summary/gate, compact
  mechanical notices) are pattern snapshots — their producers keep their own
  wording; change there must update `core/elision.ts`.
- **Budget accounting fix**: elided values count at a fixed cost in
  `maxAgedArgChars`, so the longer namespaced markers cannot squeeze multi-key
  calls into the `_aged` fallback (which would drop all keys and was larger than
  the digest it replaced).

**Breaking-ish note**: degraded-arg wire bytes change (marker form) — live
sessions incur a one-time prefix-cache invalidation when their first aged view
rebuilt. `ageToolArgs` semantics are unchanged (only results already aged;
keys preserved; legal JSON; error results never degraded; write-once).

**存量损害**：两条提交信息为占位符的历史 commit（`e886cb13`、`4f83515`）与
会话内已污染的参数记录未改写（历史改写待拍板）；旧形态参数再次进入执行会被
守卫拒收并可自愈。

### feat(engine): wire dump records raw tool_call arguments on the response side

`observability.llmRequestDump` previously captured request bodies only, so
OP-TOOL-1 could not adjudicate "model raw output vs engine rewrite". Response
traces now record per-tool-call `arguments` verbatim (stream: byte-exact
accumulation keyed by id → index, `raw: true`; chat: serialized with
`raw: false`), with `id`, `argumentsChars` (full length), explicit
`truncated` (head+tail capture — tail-anchored marker evidence preserved),
`complete` (stream cut detection), `parseError` and `ambiguous` flags. Nothing
flows back into model context (disk-only).

Verification: `npm run build` / `npm run lint` / `npm test` (4570 passed) /
`arch/check-sync.sh` all green. Independent review (1 blocker + 8 major +
10 minor) — B1 trailing-whitespace bypass, O(n²) marker scan, budget
regression, missing trace `id`, head-only truncation and the vocabulary gaps
are fixed in this batch; remaining debt: guard telemetry + retry circuit
breaker, `trimSession` full-index re-parse cost, `TOOL_CALL_ARGS_CAPTURE_CAP`
config exposure.

## v0.107.1 (2026-11-11)

### fix(gateway): P0b review minors — stream terminal validation, client-tool bridge payload, boot perms, /runs robustness, shutdown await

Clears the five residual minors from the P0b review rounds (OP-P0B-1 ⑥);
an independent review pass (10 findings: 2 major, 8 minor) was run afterwards
and **all findings are fixed in this batch** (see below).

- **m1 stream terminal validation**: `/runs` NDJSON decoding extracted into a
  pure `decodeRunStream`. A cleanly-ended stream without a `done`/`error`
  terminal entry is now a **throw** (truncation ≠ success — previously silent
  success swallowed half a run); unknown entry types also fail loud; error text
  carries session/run context.
- **m2 client-tool bridge payload**: the bridge no longer fakes the tool
  execution context. `client_tool_call` now carries the real `messages`
  (payload cost accepted — handler contract promises real messages), and the
  run-side abort signal maps to a new `client_tool_cancel` notify so the
  gateway aborts the in-flight leg immediately (was: hung to TTL when the
  abort didn't route through `abortSession()`, e.g. runGuard/budget aborts).
  Gateway side uses a per-call AbortController and typed fail-loud
  `not_implemented` effect-journal stubs — the `as never` cast is gone.
  Contract note: `RunHostNotify.client_tool_call` gains a required `messages`
  field and `client_tool_cancel` is a new variant; gateway and run instance are
  version-locked (child forked from same dist), so no mixed-version window.
- **m6 boot file exposure**: boot file (provider apiKey + loopback token) is
  written `0600` and deleted by the child immediately after read — exposure
  window shrinks from "whole run lifetime" to "startup instant".
- **m7 /runs robustness**: NDJSON writes honor backpressure (await drain on
  `write === false`); client disconnect (`res` close) aborts the run through
  the `startRun` signal seam instead of spinning to natural completion; mount
  failures return 4xx (sync error surface) instead of 500 — symmetrically on
  `/control` compact; outer catch refuses a second `writeHead` after
  `headersSent` and the request handler gets a terminal `.catch` — the
  unhandled-rejection path is gone.
- **m8 shutdown**: gateway `stop()` awaits `runBackend.stop()` (was `void` —
  raced process exit against child/boot cleanup); the run child disposes
  `sessionSchedules` on close and exits on IPC `disconnect` (orphan guard for
  gateway crash).

Independent-review findings fixed in the same batch:

- **F1 (major)**: after IPC `disconnect`, `process.send` no-ops into an
  unhandled `'error'` event (`ERR_IPC_CHANNEL_CLOSED`) and crashes the
  shutdown — all send sites now check `process.connected` and absorb send
  errors via callback (graceful close stays graceful).
- **F2 (major)**: `RunHost.disposeAll()` cleared `activeRuns` without aborting
  — shutdown with an in-flight run hung until the 5s force-exit, and m1 then
  reported the forced kill as a truncation failure. `disposeAll` now aborts
  in-flight runs first (streams close with their real terminal state).
- **F3–F9 (minor)**: `error` entries preserve `name` (abort vs failure stays
  distinguishable); malformed stream lines throw with context (not a bare
  `SyntaxError`); the dead `sawTerminal` flag removed (truncation is the only
  fall-through); effect-journal stubs throw **synchronously** (a rejected
  promise in a fire-and-forget call site is an unhandled rejection);
  `clientToolAborts` is aborted + drained at `Gateway.stop()`; `messages` is
  runtime-validated at the bridge (fail-loud on protocol mismatch); boot file
  is deleted **before** parsing and cleaned up when `fork()` throws.
- **F10**: test anchors for m6/m7/m8 (boot 0600 + read-and-delete, client
  disconnect aborts the run, IPC disconnect self-terminates the child) and a
  disposeAll-abort anchor for F2.

Verified: build green; 4543 tests green (anchors: `run-stream-decode`
terminal-state table incl. name-preservation/malformed-line, `client-tool-bridge`
pairing/payload, `gateway-run-backend` disposeAll-abort, `run-remote-backend`
m6/m7/m8 e2e); lint 0 new; arch check-sync green.

Also resolves the v0.107.0 known-debt `close timed out` exit symptom with
~745 phantom FILEHANDLEs (OP-P0B-1 ⑤). Decisive A/B with the original probe
(`--reporter=hanging-process` on `tests/plugin-channel.test.ts`, whole file):
parent commit `19cd568c` = 745 ghost handles + 10s close timeout, this commit
= 0 (two runs), with the test files byte-identical between the two — so the
cure lies in this batch's shutdown/disposal fixes (F2/m8 family; individual
member not isolated). Attribution correction: **not** test-exit hygiene — the
ghosts were Node-bookkeeping shadows of undisposed shutdown work (the
lsof zero-OS-leak finding still holds). No vitest upstream defect to track.

## v0.107.0 (2026-11-10)

### feat(gateway): P0b run-instance process split — RemoteRunBackend as the sole run backend

The execution plane moves out of the gateway process. A `run-serve-child` instance
(fork + pure-data boot file + loopback HTTP NDJSON contract channel + fork-IPC host
notifications) now hosts the full execution assembly (providers, plugin host,
session-store writer, `RunAssembly`, `RunHost`, delegation). `RemoteRunBackend` is the
sole `RunBackend` implementation and `InProcessRunBackend` is deleted; the contract
surface is `startRun` / `control` / `health` (`stop` is lifecycle). The run instance
keeps zero resident trigger surfaces (no `AgentRuntime`/`TriggerSource`; schedules open
store-only) — trigger/execution face separation per arch/service-topology.md §4/§5.4.

- **S1 closed**: delegated child runs execute through the same execution leg
  (`activation/delegated-run.ts` → `host.startRun`, admission gate + in-flight counting +
  abort), so retire judgment sees child runs; `attach`/`child-run` no longer hold a bare
  runner. `RunRequest` gains per-run `systemPrompt`/`rightsCeiling` (D3 stays
  tighten-only: the Runner intersects with the template ceiling) and `startRun` accepts
  an external abort signal (D4 projection).
- **S2 closed**: `buildAgent` assembly kernel extracted into `RunAssembly`; face wiring
  (approval / commands / memory / delegation) goes through hooks.
- **Tool face follows the execution node** (§10): global tools assemble at the run
  instance via `integration/tools/assemble.ts` — the single source shared with the CLI
  daemon (its inline assembly is removed; `resolveSummaryToolBindings` moved into engine).
  `GatewayConfig`/`toGatewayConfig` carry `summary`/`webSearch` for run-node assembly.
  `ask_user` crosses the boundary as a notify/control pair (`ask_user_request` /
  `askUserReply`, two-state outcome; failure rejects so the tool fails loud).
- Session retrieval projection (`sessions.index.db`) attaches to the run node's store
  (the writer side); index loss degrades to scan-only search with an explicit warning.

### fix(gateway): process-split correctness (independent-review blockers/majors)

- Global tools were silently absent in remote mode (production agents saw only builder
  tools) — assembly now runs at the run node via the shared factory (above).
- `SessionScheduleService.open()` unconditionally re-armed schedules and started the
  tick, and `set`/`update`/`resume` re-armed through `arm()`: a run node consumed due
  jobs through an empty wakeup with bookkeeping already advanced. `arm` is now a
  first-class service state (`open({arm:false})` gates arming everywhere); the trigger
  face stays solely at the gateway (its 60s fallback tick picks up run-created jobs
  from the shared store). Regression anchor covers the silent-consumption shape.
- Client tools registered before the first mount were dropped (ops applied to mounted
  agents only). `RunHost` keeps a live registry and replays it at mount.
- Visibility freshness contract: `ClientToolVisibilitySnapshot` carries `expiresAt`;
  the gateway refreshes with periodic diff-pushes (TTL lapse is heartbeat-absence —
  a time-based state has no event to hook, so the producer is a timer) and the run
  side fails safe to hidden once a snapshot expires (unknown liveness → not visible).
- Knowledge admission-state mirror is a three-segment contract (source-point
  subscribe before runtime start → attach snapshot → post-attach sync): runtime
  transitions (degrade / self-heal) now reach the run-side gate instead of freezing
  on the boot snapshot.
- `syncKnowledgeState` had no producer at all before: `knowledge.required` could
  refuse every run while the panel showed ready (or stay pinned after self-heal).
- Runtime-added/rebuilt agents never registered skill/user commands at the command
  router (empty hooks) — discovery results flow via `commands_registered` now (hook
  signature carries `agentId`).
- Session-index projection has a single writer now (the run node's store — the §3
  session writer); the gateway-side store no longer projects. Gateway's residual
  write paths skip projection until §9.6 lands (registered debt).
- The knowledge admission gate closure is a single-source factory
  (`makeKnowledgeAdmissionGate`) shared by run-serve-child and tests; daemon's dead
  inline assembly blocks (and their fake-success log) are removed.
- `startRun` synchronous throws leaked the abort controller/listener into `activeRuns`.
- Manual-compact events lost Observer Hub ingestion (F22) and drifted the event
  `data` envelope; the Hub seam now records honestly (see Known debt for the
  cross-process observer gap).

### Intentional convergences (declared, not deferred)

1. No-inbox execution leg is the documented default: `RunDispatcher` keeps the original
   trigger queueing semantics remotely; inbox merge is an in-process optimization only.
2. Client-tool visibility snapshots may lag by one push interval; the wire carries
   `expiresAt` and an expired snapshot fails safe to hidden (unknown liveness → tool
   not visible).
3. Runner-side hook observations cross the process boundary as shared-file writes
   (`globalThis` cannot); tests observe via the shared store.
4. Test transport seam: `control` reaches the local kernel directly; the HTTP hop is
   covered by the protocol e2e (run-remote-backend).
5. Circuit breakers are per-process (no cross-process breaker state in this phase).
6. Schedules dual-instance transition: ticking/rearm live only at the gateway.

### Known debt (registered, not fixed here)

- Agent-subsystem timers (backfill, memory health probe) are per-run-node; multi-instance
  de-duplication rides the P0c lease work.
- Gateway retains whole-package session writes at five call sites plus
  `patchSessionMetadata`; the §3 single-writer invariant is not fully established across
  processes — routed with the session service (arch/service-topology.md §9.6). Gateway
  residual writes therefore skip the session-index projection (run node owns it);
  zero-message sessions arrive in search at the next boot reconciliation.
- Cross-process Observer gap: run-node observations land in the run node's ObserverHub
  (exporter sink) — the gateway's in-memory timeline does not cover run events; the UI
  live view rides WS. Face ownership rides the P1 observer/service split.
- `RunBackend` type still carries P0a scaffold surface (mount/handle face); the
  client-contract type split rides P1.
- Minor review items (stream terminal-state validation, client-tool bridge payload
  narrowing, boot-file permission hardening, `/runs` backpressure/disconnect handling,
  shutdown awaiting) are tracked in arch/open-problems.md.
- vitest run exit shows a `close timed out` warning (phantom FILEHANDLEs on some
  multi-test files); lsof confirms zero OS-level FD leak — test-exit hygiene only.

**Verification**: three-package tsc green; full suite 434 files / 4526 tests green
(incl. new anchors for delegated-leg mapping, per-run overrides, external abort signal,
client-tool replay); lint green (typecheck-tests 0 new). Two independent review rounds
(P0b body, then the fix face); every accepted finding is fixed or declared above.

**Breaking notes**: `InProcessRunBackend` is removed (internal scaffold, no external
consumers); `resolveSummaryToolBindings` now lives in engine (daemon re-export kept);
`RunRequest` gained optional `systemPrompt`/`rightsCeiling` fields and `RunControlOp`/
`RunHostNotify` gained the `askUserReply`/`ask_user_request` pair (additive).
