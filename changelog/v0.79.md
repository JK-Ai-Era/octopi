## v0.79.0 (2026-10-16)

### feat(security): SEC-7 HITL single model (HitlDecision + decision cache)

**问题**：HITL 三套半成品并存——`confirmHighRisk`/`confirmEffect` 走 askUser 是/否；`ApprovalManager` 导出却从不被调用；Gateway `pendingApprovals` + Web `/approvals` API 齐全但 `createPendingApproval` 无调用方。嵌入方极易接错面。

**拍板**（`arch/security-open-issues.md` SEC-7）：收成单模型，**不做兼容过渡**。唯一强制面 = 两条钩子；决策统一 `HitlDecision`；session/always 缓存放引擎；删 ApprovalManager；Gateway 确认走 pendingApprovals；`askUser` 只留 `ask_user`。输出侧永不确认；无人值守 fail-closed。SEC-5 分布式 Lease 延期迁 `OP-LEASE`。

**调整**：

- **core `HitlDecision`**：`'deny' | 'approve' | 'approve_session' | 'approve_always'`；`confirmHighRisk` / `confirmEffect` 均返回该值（不再 boolean / `'allow'|'deny'`）。
- **`human-in-the-loop/decision-cache.ts`**：`HitlDecisionCache` + `resolveHitlDecision`（查缓存 → 调钩子 → 记账）。key：high_risk=`toolName`，effect=`intent.kind`。`deny` 与一次 `approve` 不缓存；always=进程生命周期。
- **删除** `approval-manager.ts` 与 `ApprovalProvider`/`ApprovalLevel`/`ApprovalPolicy` 死契约。
- **`run-agent` / `gateEffect`**：走 `resolveHitlDecision`；session 作用域随 RunScope。
- **Gateway**：`requestApproval` 挂 `pendingApprovals` 并等待 UI（超时/取消 → deny）；`resolvePendingApproval` 支持 `scope: once|session|always`；`confirmHighRisk`/`confirmEffect` 改走审批面（不再 askUser）；abort 时取消未决审批。
- **Web SDK/Store/WebUI**：`ApprovalScope`；审批事件 `approval.pending/resolved`；审批卡（允许一次 / 本会话允许 / 始终允许 / 拒绝）。
- **文档**：SEC-7 结论、SEC-5 → `OP-LEASE`、NEXT-STEPS、KNOWN-ISSUES EN+ZH、HITL README。

**测试**：`tests/harness/hitl-single-model.test.ts`（缓存代数 / in-flight 去重 / TTL / fail-closed / session·always 免再问 / deny 不记账）+ `tests/gateway-approval.test.ts`（scope 映射 / 超时 / 取消 / 双 resolve / 会话过滤）+ `effect-confirm.test.ts` 改 `HitlDecision`。

**审查加固（独立 review 后）**：

- Web store `listApprovals(sessionId)` 按会话过滤（修跨会话泄漏）。
- `deleteSession` / `stop` / `abortSession` 取消未决审批并 `clearSession` 缓存。
- `evictOldApprovals` 淘汰 pending 时标 rejected + 广播；不淘汰刚插入条目。
- `resolveHitlDecision` in-flight 去重（同 key 并发共享一次 ask）。
- 审批 id 用完整 UUID；`normalizeRiskLevel`；`clearTimeout`；审批卡文案披露 session/always 按工具/效应类型记账。
- `docs/architecture.md` §3.4 EN+ZH 对齐 SEC-7 单模型。
- `approve_always` **按 agentId 分桶**（信任级不同不共享）；缺 scope id 降级 one-shot。
- 无 RunScope/sessionId 时确认钩子直接 deny（不建不可见审批卡）。
- 删除死类型 `ConfirmEffectIntent`；`ConfirmEffect` 收敛为 `ToolExecutionContext['confirmEffect']`。
