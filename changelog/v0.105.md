## v0.105.5 (2026-11-10)

### feat(plugin): plugin tooling — octopi plugin doctor/sync (P6-5)

P6 closes its five gaps with the plugin lifecycle tooling. `octopi plugin
doctor [dir]` (local, no LLM, exit 1 on errors) checks manifest JSON/schema,
the engine range against the installed engine (the loader's own rule via
`satisfiesEngineRange`), entry presence, `plugin-state/<id>` permissions
(0700/0600), deployed-copy drift against `OCTOPI_HOME/plugins/<id>`, and
`secretOptions` keys vs `configSchema.properties` — findings use stable ids
(PLG001-007) with warn-not-block vs error-refused severity. `octopi plugin
sync [dir] [--into <root>]` deploys atomically (staged beside the target,
renames swapped with rollback on failure — never half-written), excludes
dev-only files, removes stale deployed files, and prints the restart notice:
in-process plugins have no hot reload in v1 (no dev-mode watch — decided
boundary), so sync says restart instead of pretending. `plugin init`
scaffolds a project that passes doctor clean after its first
`npm run build` (before it, doctor reports the missing `dist/` entry exactly
as the loader would refuse it).

- Independent review (del-a0b2e41e) falsified the first cut's "atomic
  deployment" claim and every finding was verified and fixed: a failed
  rollback used to delete BOTH copies (now `swapIn` keeps the backup on disk
  and reports its path — injectable rename, failure-tested); interrupted runs
  left `.sync-*` scratch dirs whose manifests poisoned loader discovery (now
  swept first, and the loader never treats dot-dirs as plugin candidates);
  `plugin sync` onto its own deployed copy destroyed dev artifacts (now
  refused); symlinks were silently dropped yet certified as matching (now
  inventoried explicitly — internal links deploy by content, root-escaping
  links are refused); doctor certified entry paths the loader rejects (the
  entry check now shares the loader's own root-escape rule, exported as
  `resolvePluginEntry`); `--into` before the positional consumed the flag
  value as the source dir (value-flag parsing now follows requireFlagValue
  semantics); doctor no longer crashes on a non-directory deployed path.
  Also: PLG007 reports "cannot compare" (info) instead of a false ok when
  `configSchema` has no properties and uses `Object.hasOwn`; PLG005 walks
  state subdirectories with its own rules; the docs state the
  rename-atomicity (no fsync) boundary.
- Verified: build/lint/full suite (431 files, 4490 tests)/arch-check-sync
  green; 25 cases cover every doctor check (healthy/error/warn states),
  drift→sync→drift-clear, sync change reporting, invalid-manifest
  non-disturbance of the existing deployment, self-sync refusal, scratch
  sweeping, symlink content-copy and refusal, loader-rule entry checks,
  swapIn rollback preservation (injected rename failures) and stale-file
  removal/dev-file exclusion.

## v0.105.4 (2026-11-10)

### feat(plugin): host storage primitives — api.stateDir + api.secrets vault, manifest secretOptions (P6-4)

Plugins get the two persistence primitives the three real plugins were
hand-rolling: **`api.stateDir`** (per-plugin private state directory
`OCTOPI_HOME/plugin-state/<id>`, created 0700 via `api.ensureStateDir()`;
plugin-state is now part of the documented home layout) and **`api.secrets`**
(`get/set/delete` over the Host credentials vault — AES-GCM, values in the
`plugin:<id>:<key>` namespace bound to the plugin as the only resolvable
consumer; plaintext is short-lived and never echoed by meta surfaces). The
governance layer gained `CredentialStore.reveal()` (plaintext resolution with
the same SEC-3c binding rules; `resolve` now shares one implementation point)
and `plugin` scope/consumer kinds. Invalid keys and empty values are rejected
with real errors.

**M4 secret echo**: manifests declare `secretOptions` (option keys holding
secrets); `GET /config/models` redacts those values to the same
`RedactedSecret` view as `apiKey` (`{configured, ref}`) instead of echoing
them — previously `options` was passed through verbatim.

**weixin example adopted**: runtime state (`baseurl`, cursor) now lives under
`api.stateDir`; `bot_token` lives in the vault (skipped-write on cursor-only
saves; dead-token parking clears the vault entry too). Standalone use without
vault injection keeps the legacy inline-token file. Deployments migrate with
`migrateLegacyState()` (one-shot: the pre-P6-4 `credentials/` single file is
adopted, its inline token moved into the vault on first save). Manifest
`engine: >=0.105.4` + `secretOptions: ["verifyCode"]` (first real declarant).

- Independent review (del-03c100bd) caught a silent-destruction blocker in the
  first cut: the persistence split wrote the token-less file BEFORE the vault
  write, so on an unprovisioned master key the pairing token was lost across
  file, vault and the unlinked legacy file while the channel only showed
  "not paired". Fixed by inverting the ordering (the vault must accept the
  token before the file drops it; vault failures keep the token inline and log
  loudly), surfacing vault read failures instead of masking them as
  "unpaired", and making dead-token parking delete steps independent.
  Also from review: echo placeholders are write-safe — a `RedactedSecret`-
  shaped value for a declared key on upsert restores the stored value (same
  rule as blank apiKey), so a web-console edit can no longer overwrite a real
  secret with `{configured, ref}`; redaction fails closed (whole `options`
  masked) when the plugin contribution is not in the live registry; legacy
  migration only adopts the default location (an explicitly configured
  statePath is never moved); `secrets.set` revokes leftover foreign bindings;
  `ensureStateDir` reports chmod failures instead of swallowing them;
  `redactSecret` is the single masking implementation (`${VAR:-fallback}`
  form preserved).
- Verified: build/lint/full suite (430 files, 4472 tests at land time)/arch-
  check-sync green; 20 new cases cover 0700 stateDir creation/tightening,
  vault round-trip, namespace privacy (cross-plugin read/overwrite/delete
  rejected), meta no-plaintext, master-key fail-loud, default stateDir
  derivation, expiry parity, manifest secretOptions validation, key-level
  echo redaction + fail-closed masking + placeholder round-trip, weixin
  vault/file split, cross-restart restore, inline-token self-migration, vault-
  failure token retention (the blocker's regression case), and one-shot legacy
  adoption.

## v0.105.3 (2026-11-10)

### feat(plugin): contribution instance registry + api.getContributionInstance (P6-3)

Factory-backed contributions (providers, channels) now register the runtime
instances the Host serves. **Birth = Host acceptance**: `record.acceptInstance`
runs after contract validation and records the factory product itself (plugin-
specific methods live only there; with `observability.llmRequestDump` the Host
routes through a decorator copy that forwards SPI calls to it — acceptance runs
before decoration so the copy's `dispose` forwarding closes the retirement
chain). The registry's "live" set matches what the Host routes to: rejected
factory products are never tracked, and a pre-built instance whose config
apply aborts before install is rolled back (`discardInstance` resurrects the
instance it superseded). Retirement has two idempotent triggers: physical (the
instance's `stop()`/`dispose()` runs — recorded on request regardless of
outcome; `dispose` is defined as a marker when the provider has none) and
logical (routing removal — hot-reload replace supersedes, provider removal /
config reset marks immediately; deferred disposal is only the physical
backstop, lookup stops returning at retirement). Re-accepting a retired
singleton revives its entry. Instances whose retirement cannot be tracked
(frozen/sealed) are never registered and never patched — the Host logs an
explicit warning and its contract validation stays the authority on broken
adapters.

Plugins reach their own live instance through the narrow lookup
`api.getContributionInstance(kind, id)` with exactly-one semantics: one live
instance is returned; otherwise a real error distinguishes never-instantiated /
retired / ambiguous multi-live (naming the instance labels) / not a
contribution of this plugin; unknown kinds and non-string ids are rejected at
runtime (the API is reachable from plain JS). This replaces module-closure
bridges — the weixin example's `weixin_pair` tool now queries the registry
instead of a shared `let adapter`. Cross-plugin lookup is deliberately outside
the v1 contract. Public docs updated in both languages.

### fix(gateway): provider teardown paths retire displaced instances

`resetRuntimeConfig` rebuilt the provider map with bare delete/overwrite —
displaced instances were neither disposed nor retired (a pre-existing resource
leak); they now go through `retireProvider` like `replaceProvider` /
`removeProvider`. `retireProvider` additionally marks logical retirement in
the plugin instance tables at routing removal, so lookups never hand out an
instance the Host no longer routes to during the 30-minute dispose grace
window.

- Verified: build/lint/429 files 4444 tests/arch-check-sync green; 26 cases
  cover acceptance births and rollbacks (incl. the real
  `createProviderFromConfig` / `createChannelAdapterFromConfig` paths, the
  no-phantom-on-rejection invariant, and wire-dump dispose forwarding),
  physical + logical retirement, supersession and revival of singletons,
  aborted-acceptance rollback with resurrection, kind/id validation,
  frozen/broken adapter non-tracking, repeated publish, a real weixin plugin
  bridge round-trip incl. post-retirement state, and gateway
  `resetRuntimeConfig` grace-window disposal (fake timers).

## v0.105.2 (2026-11-10)

### feat(plugin): optional ChannelAdapter.status() + gateway health (P6-2)

The Channel SPI gains an optional `status()` probe
(`{ state: 'running' | 'dormant' | 'degraded' | 'retiring', detail? }`). The
gateway `/health` endpoint reports every channel's state via
`getChannelStatuses()`: adapters without `status()` truthfully default to
`running` after a successful `start()` (the start/stop contract makes "started"
the real state), a `status()` that throws degrades only that channel's entry,
and adapters not yet started report `dormant`. The weixin plugin implements
`status()` with its real lifecycle semantics (dormant when unpaired or after
dead-token parking, degraded with the poll error while backing off, running
when paired and polling). Public docs updated in both languages.

- Verified: build/lint/428 files 4418 tests/arch-check-sync green; new tests
  cover the gateway default/verbatim/throwing paths and weixin
  dormant/running/degraded transitions.

## v0.105.1 (2026-11-10)

### refactor(plugin): contribution-kind descriptor table (P6-1)

The six contribution kinds (tools/commands/hooks/services/providers/channels) now
share one declarative descriptor table (`plugins/contribution-kinds.ts`). The
staging write path (`stageContribution`: reserved-id check, per-plugin
uniqueness, kind-owned insert — including hooks' priority-sorted Map insert) and
the read path (`forEachStaged`, which pairs entries with their keys) live on the
descriptor, so the table owns every pipeline semantic: staging uniqueness,
reserved-id rejection, publish ownership conflicts, manifest claims, manifest
key uniqueness, and manifest↔registration reconciliation. The previous four
hand-copied pipeline sites (PluginApi register dedupe, registry publish loop,
loader claims + bidirectional check, manifest assertUnique block) all read from
this table; adding a new contribution kind is now one descriptor plus typed
surfaces (register signature, staging slot, record type, manifest schema
field) instead of four copied pipeline blocks.

- **Behavior preserved**: atomic publish, `{pluginId, ...entry}` record shape,
  public getters, and all pinned error wordings (all 159 pre-existing plugin
  tests pass unchanged). Hooks remain the deliberate semantic exception
  (multi-handler per name, no cross-plugin ownership) while their staging write
  path is table-owned like every other kind.
- **Diagnostics**: service empty-id and duplicate errors are now two precise
  messages; command duplicate reports the normalized name; when a service
  registration is both a duplicate and carries an invalid timeout, the timeout
  error now reports first (shape validation uniformly precedes staging checks,
  matching tools/commands/providers/channels).
- Verified: build/lint/428 files 4409 tests/arch-check-sync green;
  `tests/plugin-contribution-kinds.test.ts` locks the table semantics, including
  publish-time owner-conflict atomicity and the `before_agent_reply` single-owner
  rule (independent review del-bd446d3b: 0 blocker/major; all findings fixed).
