## v0.108.5 (2026-11-12)

### fix(gateway): P0c 评审 MAJ 修复批 — 回执路由 / control 分类 / 跨版本自救 / 存活闭环

- **MAJ-1 回执路由串台与泄漏**：回执 id（`ap-/ask-/ct-`）由进程内自增改 `randomUUID`（多实例同 id 碰撞 → A 的审批会批掉 B 的调用）；回执表终态即删（成败都删）；`unregister` 清该实例全部回执项。
- **MAJ-2 control 分类漏网**：`syncKnowledgeState` 入 fleet-wide fan-out（每实例一份 knowledge 准入快照，漏同步=旧快照 fail-open）；`contextHealth` 归最闲实例透传（曾 unrouteable 恒失败、静默退化磁盘扫描）；`syncKnowledgeState`/`askUserReply` 调用点统走 fleet（原直连 run-0 绕过路由）。
- **MAJ-3 跨版本自救被健康门卡死**：`/smoke` 为 v0.108.2 新增端点，旧构建 404 会被误判冒烟失败挡回滚（根需求「切回旧版本」失效）。`smoke()` 判 HTTP 状态；404 → `unavailable` 显式降级标记，健康门降级为 health+guard 判定并 warn（fail-loud, degrade explicitly）；`smoke()` 拒绝非 2xx。
- **MAJ-5 存活闭环**：`RemoteRunBackend` 新增 `onExit` 回调——实例退出即移出路由面（sticky/pulse/回执随 unregister 清，防 sticky 会话黑洞）；drain **开始**即疏散（sticky 迁走 + pulse 归属转移触发，§5.2）；draining 的 sticky 亲和改为失效（修订 §7.1 旧语义：drain=停止接一切新 run，否则排空永不收敛）；drain 重入改为继续等到 idle（原超时后重试假成功）。
- **MIN-1/8/14**：spawn 回填真实 port/pid（`InstanceBackend.info`）；探针类 fetchJson 带 30s 超时（`/runs` 长流不受限）；ops 状态迁移统一走 `registry.setState`（单一写路径）。
- **验证**：新增回归锚 4 个（contextHealth/syncKnowledgeState 路由、回执终态即删+注销清理、draining 疏散、smoke 跨版本降级）；全量测试套件绿。


## v0.108.4 (2026-11-12)

### fix(gateway): 委派工具挂载回归 — 缺省默认开启被误当禁用（P0b S2）

- **症状**：P0b 进程拆分后 `delegate_dispatch/list/get/cancel` 从 agent 工具面消失（未显式声明 `delegation` 的 agent 全部丢委派能力）。
- **根因**：`run-serve-child.ts` 委派接线的外层守卫 `if (delegation !== undefined)` 直接读字段——把「未声明 = 缺省开启」（`registry-types.ts` AgentDelegationPolicy 明文：缺省默认具备委派能力，一律经 `effectiveDelegationPolicy()` 取生效值）当成「未声明 = 禁用」。P0b 前 gateway 侧 `wireDelegation` 判定正确（`effectiveDelegationPolicy(a.delegation).canDelegate`），S2 迁移时守卫语义换错。同型直接读字段点已全仓排查（仅此一处）。
- **验证**：smoke 报告 tools 明细新增工具名清单；e2e 新增回归锚「未声明 delegation 的 agent 必须挂 `delegate_dispatch`」；全量测试套件绿。


## v0.108.3 (2026-11-12)

### test(gateway): P0c-4 验收演练 — 自救 + 多活（真进程 e2e）

- **自救演练**（§6 验收 1）：v-good 就位 → 故意起坏版本（入口存在但启动即炸的 fixture 构建）→ 起不来即 failed 终态、不入路由、**流量留旧版本**（新会话仍进 v-good）→ 修好过门 → promote → 新会话进 v-fixed → drain v-good（停机注销）。全链真进程。
- **多活演练**（§6 验收 2）：同版本 2 副本（挂起 LLM 服务器制造在途）→ 两会话 sticky 分到**不同实例**（least-load 记账生效）→ 脉搏归属全 fleet **唯一持有者**（双副本同 key 自述 → 归属单实例，经归属实例打点应答）。
- **语义修复（演练逼出的真缺口）**：`pickLeastLoaded` 按 `RouteConfig.versionPointer` 过滤版本（§4.2「新会话按 RouteConfig 定版本」——P0c-2 单版本下漏实现，promote 后露馅）；`FleetRunBackend` 构造注入共享 RouteConfig（与 FleetOps 同源）。无该版本 ready 副本时 fail-loud。
- **验证**：演练 2/2 绿 + 全量测试套件 4606 绿。


## v0.108.2 (2026-11-12)

### feat(gateway): P0c-3 健康门 + 版本化 spawn + 生命周期 ops

- **健康门**（§4.3，Q2 落地含冒烟）：probe 链 = health 可达 → `POST /smoke` 冒烟 → **守卫在位核查**（配置含 securityIntegrity 而实例报 `absent` 即拒——收口跨版本漂移闸 fail-open 缺口）。冒烟为独立通道（不是 run）：强制走一遍惰性装配热路径 + 逐 agent 工具面枚举 + no-LLM 应答（contextHealth），报告 `RunSmokeReport` 如实入 checks。
- **health 契约**：`securityGuard: 'armed' | 'absent'` 自证字段（run-serve-child 按 configPath 自建守卫的现地报告）。
- **版本化 spawn**（§4.4）：`RemoteRunBackend.start` 支持 `buildRef`（构建产物根直指入口，跨版本拉起）；`RunVersion { version, buildRef }` 语义就位。
- **FleetOps**（§5.2 原语）：`spawn`（逐个过健康门，failed 终态不入路由、流量留旧版本）/ `probe`（复检，拒则驱逐 + 停机）/ `scale`（对齐副本数，多退 drain 少补 spawn）/ `promote`（versionPointer 前移，Q3=A 运行态）/ `rollback`（旧构建起新实例 + promote，半败不切流量；§6 拍板 #6）/ `drain`（不接新会话 → 等在途 run → stop → 注销；幂等、failed 终态拒 drain、超时 fail-loud）。
- **修复**：`pickLeastLoaded` 不再把新会话分给 draining 实例（§4.5「draining 不接新会话」；sticky 亲和仍保持）；FLEET_WIDE_OPS 清除不存在的 `probeAgent` op。
- **验证**：supervise-probe 10（判据矩阵 + ops 状态机）+ supervise-fleet 9 + **真进程 e2e**（spawn→健康门→smoke→drain；坏 buildRef 拒入路由）+ 全量测试套件 4604 绿。

- **supervise/registry**：InstanceRegistry（事实登记，failed 终态不可复活、重复注册 fail-loud）+ RouteConfig（期望状态；Q3=A 拍板落地：运行态 + config 播种，`RouteConfig.seed()`，不落盘）。
- **supervise/fleet-backend**：FleetRunBackend 对 gateway 呈现 RunBackend 契约——`startRun` sticky 亲和（§7.1）+ per-session 单飞闸门（§5.1 run lease 近似，同会话并发第二个 run 直拒）+ 最少负载分配；failed 实例亲和失效换实例，draining 保持亲和。
- **control 四类路由**（实现期补全分类，已记设计稿 §4.2）：session-scoped → sticky 实例；fleet-wide 维护 op（retireAgent/reloadAgent/setClientTools/reattestSecurity/probeAgent）→ fan-out 全部实例（聚合失败指名实例，fail-loud）；`pulse` → 归属实例单发；**点对点回执**（`approvalReply`/`clientToolResult`/`askUserReply`，第三类——不带 sessionId，按 notify 源登记的回执路由表回源实例，一问一答成功即拆）。

- **pulse lease 归属**：归属表移 FleetRunBackend（单一事实源）；PulseScheduler 多实例化——首见分配 / 持有实例消失转移 / key 消失拆除（resync 对账）。
- **接线**：`getRunBackend()` 走 fleet（消费点零改动）；装配测试缝注入面从 monkey-patch `runBackend` 迁移为 `fleet.register`（3 个测试文件，传输缝语义不变）；`gateway.start()` 换代语义（同槽位先注销旧登记，重试路径不再撞防重复护栏）。
- **验证**：supervise-fleet 9（路由四类/单飞/亲和/聚合/归属）+ pulse-scheduler 7（含归属转移）+ 全量测试套件 4593 绿。
