## v0.117.0 (2026-11-17)

### feat(errors): 错误分类域×档——工具错误不再冒充「模型服务出错了」

**问题**：工具执行错误（参数错误、ENOENT、exit≠0、守卫拦截）与会话操作错误都塞进 provider（模型服务）错误分类器，未命中关键词落 `server` 兜底 → UI 显示「⚠ 模型服务出错了 / 复制诊断 ID 反馈支持」——吓人且误导（工具错误模型可自救）；`rate_limit`/`timeout` 也落同一兜底；support 档承诺的诊断 ID 从未渲染。

**改法（域×档，分类/文案单源仍在 engine `config-admin/error-copy.ts`）**：

- **来源域分流**：provider（模型服务）/ tool（工具执行）/ app（界面/会话操作），`classifyFlowError(raw, source)` 取代 `classifyProviderError`（语义即契约，provider 文案表不再被工具/操作错误复用）。
- **处置档落地**：self-heal（工具执行失败/守卫拦截——不进错误卡，工具卡低调行，agent 自会调整）/ user-action（卡+出路+raw 折叠）/ support（卡+诊断 ID+raw 折叠；ToolCard/assistant 行/system 消息三处渲染兑现「复制诊断 ID」承诺）。
- **码集扩**：provider 新增 `timeout` / `rate_limit`（原落 server 兜底）；`ETIMEDOUT` 语义归 timeout；context 判定复用 core `isContextLengthErrorText`（Anthropic "prompt is too long"、Gemini "input token count" 不再落吓人卡）；`429` 词边界化。
- **工具域细分**：blocked 覆盖真实 violation 文本（beforeToolCall 阻断无 `Blocked by SecurityGuard:` 前缀，修死分支）；internal 收紧为「堆栈 + octopi 包内路径」（用户脚本 stderr 不再误升级 support）。
- **语义归位**：`engine.error`（Run 终态通用通道）走 app 口径，不再一律「模型服务出错了」；system 消息族中文化（aborted/truncated/compact/retry/budget/stream-fallback）；`security.blocked` 审计语人话映射（`securityBlockedCopy`，与工具域 blocked 共用 `securityViolationKind` 单源）+ reason 附注保留可诊断性；诊断 ID 生成单源 `makeDiagnosticId`。
- **类型契约**：`probeProvider`/`classifyProbeError`/gateway `probeError.kind`/CLI `ProbeLabels` 跟随放宽（union 扩容，向后兼容）；`PROBE_ERROR_KINDS` 由 Record 全键派生（扩类编译期强制）。

**breaking note**：webui 内部 API `classifyProviderError(raw)` → `classifyFlowError(raw, source)`（全调用点已改）；system error 消息不再直出 raw（历史回放一致）；诊断 ID 格式去 `diag-` 前缀；webui 构建配置补 `@octopi-agent/core/loop/*` 映射（vite alias + tsconfig paths）。

**独立评审（del-6762398a）**：M4（用户面与 core 两套 classifyError 相反结论）/ M5（诊断 ID 承诺落空）/ M6（blocked 死分支）/ M7（engine.error 语义错位）已修；Minor（429 词边界、internal 过宽、OnboardingWizard 类型漂移、CLI 手写码表、app 域 raw 折叠、注释口径）全清。

**验证**：error-copy 9 + error-card-classify 12 + conversation-adapter 57 绿（域×档矩阵、真实 violation 文本、跨 provider 措辞、诊断 ID 兑现断言）；全量 **5163 绿** / lint 0 / build ✓。
