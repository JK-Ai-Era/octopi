## v0.89.2 (2026-10-24)

### refactor(runner): 收编 `requireCredentialBindings` 的等价派生

`runner.ts` 组装工具上下文时写的是 `effectMode === 'untrusted' || effectRequireCredentialBindings`，而 `effectRequireCredentialBindings` 在解析策略时已是 `config.requireCredentialBindings === true || requiresJail(eff)`。

`requiresJail(eff)` 判的是 `requestedMode === 'untrusted' && mode === 'untrusted'`，且 `resolveEffectiveEffectPolicy` 里 `mode` 只从 `requestedMode` 起始、唯一改写是 untrusted 降级为 `workspace`（不会升高）——因此 `effectMode === 'untrusted'` 必然蕴含 `requiresJail`，前置判定恒被后面的项吸收。

删掉该等价项，单一来源 `effectRequireCredentialBindings`，行为不变。

**验证**：`tests/harness/effect-policy.test.ts` 新增用例锁住这条等价性（untrusted + L4 → `mode === 'untrusted'` 且 `requiresJail` true；degrade → `requestedMode` 仍 untrusted 但 `mode === 'workspace'`、`requiresJail` false；workspace/project/host 均不要求 jail），避免日后有人改动降级逻辑时这条推理静默失效。全量 3149 过 / 2 败（环境固有）/ 6 跳过。

## v0.89.1 (2026-10-24)

### fix(execution-environment): sandbox 跨块解码改 StringDecoder — 修「CJK 输出被写成 U+FFFD」

**问题**：`sandbox.ts` 逐块 `data.toString('utf8')`。子进程输出在 64KB 分块边界上切断多字节字符时，每半个字符各自解成 U+FFFD——**污染的是 stdout/stderr 文本本身，不只是统计**。实测一个 3 字节汉字被拆成 2+1 两批到达，解出 `'\ufffd\ufffd'` 而非 `'中'`；长编译输出、`git diff` 等连续 CJK 场景会反复命中，被切断处若落在 JSON/文件名里即为数据损坏。

`usage().outputBytes` 也因此虚高：它用 `Buffer.byteLength(文本)` 重算，而每个替换符是 3 字节。

**处置**：

1. 每流一个 `node:string_decoder` 的 `StringDecoder`；`close` / `error` 各冲刷一次 `decoder.end()`（截断流尾部输出 U+FFFD 是正确结果）；
2. `usage()` 改按「已捕获原始字节」计数（新增 `stdoutCaptured`/`stderrCaptured`），不再从文本重算——统计与实际捕获字节一致；
3. 上限触发口径不变（`stdoutBytes` 仍计含被丢弃块的全部收到字节）。

**验证**：新增 `tests/harness/process-isolation.test.ts` 用例（把 `中` 拆成两次写 → 断言 `stdout === '中'`、无 U+FFFD、`usage.outputBytes === 3`）。**回退实验已证该用例有效**：仅把解码改回逐块 `toString` 时，此用例以 `expected '\ufffd\ufffd' to be '中'` 失败、其余 11 例仍绿。全量 3149 过 / 2 败（`getProcessName`、`identifyPortOccupant` 沙箱固有）/ 6 跳过；`lint` 绿。

## v0.89.0 (2026-10-24)

### feat(config)!: `agents[].home` / `skillDirectory` 纳入路径契约 — 修「`~` 建字面目录、相对路径把 agent.db 绑到启动目录」

**问题**：v0.87.5 给 `agents[].workspace` 与 `effectPolicy.transactionRoots` 定了「绝对路径或 `~` 形态、拒相对」的契约，`home` / `skillDirectory` 却仍是自由 `z.string()`。两个可实测的后果：

1. `"home": "~/agents/x"` 不展开 → 字面创建 `./~/agents/x`，persona / skills / `agent.db` 全落错地方；
2. `"home": "./agents/x"` 不校验 → 随进程 cwd 解析；daemon 换个启动目录就是换一份记忆库（`wireAgentBuilder` 的 `dbPath: join(agentHome,'agent.db')`）。

第 2 条与 workspace 契约直接矛盾，且**静默**：没有任何报错，只是数据落在别处。

**处置（三字段同规，方案 A）**：

1. **schema**：`agents[].home`、`agents[].skillDirectory` 改 `ConfigPathSchema`（绝对或 `~` 形态，`~user/…` 与相对/空串一律拒）。legacy `persona` 字符串（等价 home 的弃用形态）同规——否则它是绕过口。
2. **归一化单源**：`normalizeConfigPaths` 增补 `home` / `skillDirectory` / legacy `persona` 的 `~` 展开，`validateConfig` / `validateConfigOrThrow` / `loadConfig` 三个出口后置条件一致。
3. **库边界兜底**（不经 `loadConfig` 的嵌入方）：`wireAgentBuilder` 展开 `home`/`skillDirectory` 后再 `join()`；`AgentBuilder.agentHome()` / `.skillDirectory()` 与既有 `.workspace()` 对称展开（幂等）。Gateway 侧 `ensureCommandSources` / health 探针同步展开（`AgentDefinition` 是宿主可编程注入面）。
4. **模板与文档**：`octopi.example.json` 改用 `~/.octopi/agents/assistant`；`docs/process-isolation.md`（+`.zh.md`）路径契约表补齐三个字段与「为何拒相对」的因果说明。

**破坏性变更**：相对路径（含 `"./agents/x"`、`""`）的 `home` / `skillDirectory` / legacy `persona` 现在**加载即报错**。迁移 = 补绝对路径或改 `~/…`；`home: ""` 用「省略该字段」代替。本机 `~/.octopi/octopi.json` 已是绝对路径，无迁移动作。

**已知边界**：`octopi.schema.json` 能表达 `minLength: 1` 与说明文字（编辑器可提示），但**表达不了**「绝对或 `~` 形态」这条 `refine`——与既有 `workspace` 完全一致，真正的把关是运行时 fail-fast。

**验证**：`tests/config-path-normalization.test.ts` 扩到 14 例（三字段 + legacy persona 的「拒相对 / 拒 `~user` / 拒空串 / 展开 `~`」、`loadConfig` 端到端展开与拒绝、canonical template 守卫）；全量 3147 过 / 2 败（仍为 `getProcessName`、`identifyPortOccupant` 沙箱固有）/ 6 跳过；`npm run build`、`npm run lint`、`arch/check-sync.sh` 全绿。
