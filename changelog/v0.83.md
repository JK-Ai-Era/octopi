## v0.83.12 (2026-10-18)

### fix(engine): effect-gate file_mkdir symmetrically with file_rmdir

**问题**（NEXT-STEPS D1）：七个 fs-write 工具里 `file_mkdir` 是唯一不走 `gateEffect` 的——write/edit/delete/rename/copy/rmdir 全都过效应闸，唯独建目录静默执行。默认 `pathContainment: strict` 下 L2 在门前就拦掉越界路径（补门是 no-op），但 `soft`/`none` + `effects: host-gate` 组合下，root 外的 `mkdir` 不经宿主确认直接执行，而 rmdir/copy/rename 同场景会弹确认——「删空目录要问、建目录不问」的授权不对称；审计/SEC-7 决策缓存也看不到 mkdir 事件。

**修正**：

- `file_mkdir` 在 `mkdir()` 前补 `gateEffect({ kind: 'file.write', path, mode: 'create', transactional: isPathUnderRoots(...) })`，与 `file_rmdir` 完全同构；事务内自动放行、host-gate 越界创建须宿主确认
- 结构重排：存在性检查与门控错误**裸抛**（`effect_denied` 保持可识别，与 rmdir/copy/rename 一致），仅 `mkdir` 自身失败沿用 `Failed to create directory` 包装（ENOTDIR 裸抛等旧语义逐路径等价）；幂等早退（目录已存在）在门之前，不产生提示
- 返回补 `reversible: false` + `note: 'directory creation is not journaled for turn undo'`（与 rmdir 的诚实注记对称）

**验证**：`tests/harness/file-ops-tools.test.ts` 11 用例全过（新增 3：host-gate 越界创建提示且 deny 后无目录 + 意图字段锚定 + 裸抛契约锚定、事务内 mkdir/rmdir 均不提示（对称锚）、host-gate approve 建目录且幂等重调不再提示）；lint/build/全量 2803 过（4 个已知基线失败不变）。经独立子代理评审后收紧：错误契约用 `^effect_denied` 锚定、补 approve/幂等/对称锚用例。

## v0.83.10 (2026-10-18)

### fix(engine): admit shared temp dirs (/tmp, /var/tmp) into the POSIX jail write face

**问题**（NEXT-STEPS C4 拍板）：jail 可写面 = allowRoots ∪ cwd ∪ `os.tmpdir()` ∪ home（homeWrite），**不含共享临时目录**。env scrub 后子进程若无 `TMPDIR`，`os.tmpdir()` 解析成 `/tmp`；硬编码 `/tmp` 或回退 `/tmp` 的工具在牢笼内直接 `EPERM`（实测：vitest/vite `mkdir '/tmp/…/ssr'` 被拒）。仅靠 spawn 时透传 `TMPDIR` 治标不治本：无视 `TMPDIR` 的遗留程序、以及任何漏传 env 的执行路径（嵌入方自定义 executor 等）都会复发——兼容性不应押在部署环境的 env 配置上。

**修正**：

- `resolveJailRoots` 在 POSIX 下把 `/tmp`、`/var/tmp` 纳入可写临时面；随既有「词法 + `realpath` 双形态」发射自动覆盖 `/private/tmp`、`/private/var/tmp`（macOS 符号链接别名），Linux bwrap 的 `--bind-try` 同样受益
- Windows 零变化（用户临时目录已由 `tmpdir()` 覆盖；无 `/tmp` 语义）
- 沿用 **tmp writes not journaled（`notReversed`）** 语义不变；共享临时区对所有用户可写，留在其上的内容视为已暴露（`docs/process-isolation.md` EN+ZH 已记账）
- journal/undo 不消费 jail roots，L3 撤销语义零变化；系统树保持只读

**验证**：`tests/harness/process-jail-wiring.test.ts` 24 用例全过（新增 3：POSIX 共享 tmp 双形态 roots、win32 不含 POSIX tmp 路径、profile 由 resolveJailRoots 组合断言）；EN+ZH 文档同 commit 同步。经独立子代理对抗评审后加固：win32 用例原断言恒真（`resolve()` 会把 `/tmp` 解析成 `C:\tmp`，字面匹配锁不住守卫）改为断言真实解析形态；canonical 断言对齐生产容忍语义（不可解析时保留词法形态）；profile 断言补齐 `/var/tmp` 双形态。另同步 `package-lock.json` 版本字段（此前停在 0.83.8——`release:prep` 不刷 lockfile 的流程缺口，见 NEXT-STEPS D2）。

## v0.83.9 (2026-10-18)

### fix(engine): keep stdio sinks writable and canonicalize jail roots in the macOS Seatbelt sandbox

**问题**（macOS 部署实测暴露；Windows 上开发未覆盖）：mac-seatbelt 沙箱下 `git_*` 工具全挂（`fatal: could not open '/dev/null' for reading and writing: Operation not permitted`）、bash `> /dev/null` 重定向失败、vitest/mktemp/xcrun 往 tmp 建临时文件被拒（`EPERM`）。根因链：① 生成的 Seatbelt profile 只对 allowRoots 放行 `file-write*`，而 git 以 O_RDWR 打开 `/dev/null`（`dup_dev_null`）、shell 把 stdio 重定向到设备节点——设备不在任何 jail root 下，一律被 `(deny file-write*)` 拒绝；② jail roots 只做词法 `resolve()`，macOS 上 `/var`→`/private/var`、`/tmp`→`/private/tmp` 是符号链接别名，Seatbelt 按 canonical 路径匹配 `(subpath …)`，规则永远打不中（tmp 写全灭）。vitest 全量套件在同一沙箱下另有 19 个存量失败均为此二根因的下游表现（`git init` 挂、`spawn stdio:'ignore'` 打不开 /dev/null 报 EPERM、`/tmp` 硬编码路径写不进）。

**修正**：

- **stdio 设备写放行**（仅 Seatbelt；Linux bwrap 自建 `/dev` 天然免疫）：profile 追加 `/dev/null`、`/dev/zero`、`/dev/tty`、`/dev/std{in,out,err}` 的 `file-write*` 放行与 `/dev/fd` 子树（dup'd stdio 路径）；**刻意不放行 `/dev/ptmx`**（牢笼内不给开 TTY）
- **jail roots 双形态规范化**：`resolveJailRoots` 对每个根同时输出词法形态与 `realpath` 规范形态（去重；win32 沿用小写去重），`realpath` 失败保留词法形态（stale allowRoots 不得中断命令，bwrap `--bind-try` 容忍）；对 Linux bwrap 的 bind 同样更准确，Windows supervised 路径零回归
- **D7 语义收紧为「探测对齐 + 绝不重跑」**（经独立复审驱动的安全收紧）：`probeProcessIsolation` 新增 Seatbelt `sandbox_apply` 冒烟探测（与 bwrap `bwrapUsable` 对称）——jail 完全无法生效（如嵌套沙箱）时从一开始就是 supervised-spawn、用户命令只执行一次；wrapper 运行后的疑似建笼失败**绝不重新执行用户命令**（此前 runBwrap 的回落重跑可被伪造 stderr 触发——双重执行 + 逃逸面），`requireJail` 抛 `untrusted_jail_failed`，其余如实上报 wrapper 结果 + 降级隔离声明（`cwd-pin`）+ `securityDegraded`；runSeatbelt 补齐运行期失败处理（此前只有 runBwrap 有——平行值不对称即缺口）
- **`isJailWrapperSetupFailure` 重写**：只认**行首** wrapper 签名（`bwrap:` / `sandbox-exec:` / `newuidmap:` / `newgidmap:`），新增 `terminated` 守卫（超时/abort 击杀的命令不是建笼失败）；删除裸 `operation not permitted` 与 `unshare` 裸子串匹配（沙箱对用户命令的写拒绝恰好就是这个措辞，`unshared` 这类词都会误中）
- **`esc()` 路径转义修正**：不再静默剥离 `()`/换行（会把子路径规则错指到另一目录），改为纯引号转义；路径含换行抛 `seatbelt_path_invalid`；`resolveJailRoots` 相对根按 run cwd 解析、不再裁剪首尾空格（合法目录名可含空格）
- **requireJail 契约统一**：wrapper spawn 失败路径改为抛 `untrusted_jail_failed`（与 `run()`/D7 文档「throws」一致，此前 resolve 失败结果）
- **构建流水线恢复 bin 执行位**（新增 `scripts/postbuild-bin.mjs`，接入 `npm run build` 尾部，按 `package.json#bin` 数据驱动）：`npm run clean` + tsc 重建会把 `dist/cli/index.js` 打回 0644（npm 安装时补的 +x 丢失），POSIX 上 `octopi` CLI 直接 `zsh: permission denied`——Windows 无执行位概念故从未暴露，属同类跨平台盲区
- **测试跨平台**：autonomous-subsystem 三个测试文件 4 处硬编码 `/tmp/...` 改 `os.tmpdir()`（Windows 无 `/tmp`）；新增测试：设备放行断言、roots 词法/规范双形态（真符号链接对照）、stale roots 容忍、D7 判定含防误判（用户命令错误文本不得触发）与防逃逸断言；`tests/harness/process-jail-wiring.test.ts` 共 22 用例全绿

**验证**：`npm run lint` 零告警；`npm run build`（strict tsc）全绿；`tests/harness/process-jail-wiring.test.ts` 22 用例全过。部署至工具宿主后实证：`git_*`、`> /dev/null`、`mktemp` 三项病灶全部复活，isolation notes 可见 roots 词法+规范双形态。无绕行复跑全量 **2799 过 / 4 失败 / 5 跳过**（修复前 2772 过 / 19 失败）；4 个剩余失败与本改动无关：2 个是「在沙箱内跑测试」的固有限制（`/bin/ps` 为 setuid，Seatbelt 拒绝 setuid exec——产品进程不在牢笼内，运行时正常；普通开发机/CI 通过），2 个为 knowledge 子系统存量疑点（purgePath/gap-scan，疑似 macOS 路径别名类，另排期）。`arch/check-sync.sh` 在修复后环境可正常评估：8 条红灯全部是 `collaboration/delegation`、`orchestration` 的 arch 地图存量漂移（与本改动无关）。

## v0.83.6 (2026-10-18)

### fix(engine): make proactive compaction produce semantic summaries and gate recompaction honestly

**问题**：超长会话（工具输出密集）在上下文约 600k 触发主动压缩后，**每个 run（实为每个 LLM turn）都重复机械裁剪**，UI 反复弹 `Context compacted (621930 → 222708 tokens, 15ms)`。根因链：① `HybridCompressor` 第一级「旧工具输出截断」达标即返回，**不产出语义摘要**（15ms 就是纯字符串替换的耗时）；② `applyProactiveCompact` 拿「有无 `previousSummary`」当再压缩判据 → 摘要永远为空 → `needNewSummary` 恒真 → 复用分支永远进不去，每个 turn 重裁一次、发一次非 cached 通知；③ 「LLM 摘要缓解长会话失忆」的产品目标**静默落空**——旧工具输出被换成占位符后没有任何摘要兜底；④ 机械占位说明（`[Context truncated: …]`/`[Context compressed: …]`/`[Structural compact] …`）还会被当成摘要存进 `previousSummary`，污染增量合并输入。落盘证据：该会话 `contextCompacts` 只有 `lastProactiveMessageCount/lastProactiveTokens`，`summary` 缺失。

**修正（A 判据解耦 + B 真摘要，并经独立 review 补齐同族缺口）**：

- **判据解耦**：`needNewCompaction = 自上次压缩以来新增条数 ≥ minNew`（只看增量与冷却，不再看有无摘要）；复用分支对**无摘要状态**也可用（机械重建零 LLM、`cached: true` 不刷 UI）——存量受损会话（summary 缺失的持久化快照）恢复后立即停止每 turn 机械重裁
- **requireSummary 契约**：`CompressParams.requireSummary` 新增可选字段；主动摘要路径强制尝试语义摘要，`HybridCompressor`/`LLMSummaryCompressor` 的「已达标直接返回」短路在该模式下不生效——机械截断达标也必须补 LLM 摘要（产品意图）
- **机械占位永不冒充摘要**（同族缺口一并封死）：`extractSummaryText`（proactive/overflow 共用）与 `structuralCompact` 状态写入统一过滤占位说明（首行前缀判别，不误杀引用了这些字样的真摘要）；LLM 失败/空摘要诚实降级机械视图并攒增量自动重试
- **视图边界对齐**：head/tail 切分不再拆散 tool_call/tool_result 对（悬空调用/孤儿结果会被严格网关 400）；`summarize` 返回空正文按失败降级，不再用空正文替换中间段
- **状态语义修正**：`lastProactiveMessageCount` 仅在真正完成压缩时推进（复用重建不推进）；`lastProactiveLlmAt` 仅在真正发起 LLM 摘要时推进（机械路径不写，冷却语义恢复诚实）
- 回归测试 `tests/harness/proactive-compact-tool-heavy.test.ts`：真实 `HybridCompressor` + 工具输出密集历史走真实连线（仅 stub 外部 LLM），对照组先钉住缺陷触发面，覆盖一次性真摘要、小增量复用（cached 事件在场断言）、增量合并、失败/空摘要降级不污染、**重启恢复快照形状**（有计数无摘要）、工具配对形状校验

**压缩节奏（如实说明）**：真实压缩（LLM 摘要）受「增量阈值（默认 ≥5 条新消息）+ 冷却（`proactiveCooldownMs`，默认 30s）」双闸约束，**冷却期内最多一次**；被消灭的是「无摘要的每 turn 机械重裁 + 通知刷屏」。工具密集、turn 间隔 >30s 的长会话仍会按该节奏产生真实压缩（每次带真摘要），这是「迭代式摘要」的设计节奏；若要进一步降频可调大 `proactiveCooldownMs`，或后续改 token 增量门槛（另议）。

**跟进项（另议）**：`CompressResult` 缺 `llmUsed`/`summaryProduced` 标志（`lastProactiveLlmAt` 诚实性目前依赖默认 HybridCompressor 接线约定）；`capabilities/compact` 引擎的 head/tail 切片尚未做同样的边界对齐（手动压缩路径）。
