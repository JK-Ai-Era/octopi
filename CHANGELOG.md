## v0.109.1 (2026-11-12)

### fix(gateway): P0c 评审 MIN 批（代码件）— 状态卫生 / promote 防呆 / 跨进程写留痕 / 脉搏即时对账

- **MIN-2**：registry 新增 `forget()`（failed 历史记录清理口，非 failed 拒绝——活实例必须 drain）。
- **MIN-3**：`promote` 到无 ready 实例的版本 fail-loud（曾=新会话全 fleet 无路由目标）；`rollback` 半败收摊已过门实例（不留「不接新会话也不收摊」的孤儿）。
- **MIN-9**：session-scoped control 无 sticky（该会话从未跑过 run）时显式 warn——单机多实例下可能是跨进程写同一会话文件（进程内锁不跨进程，E7）；P1 run lease 正式化前不留静默约束。
- **MIN-11**：新增 `pulses_changed` notify——agent mount/retire 后调度器**立即** resync（曾最迟延迟一个 60s 周期，runOnStart 首跳同理）。
- **MIN-12**：`probe` 对 `starting` 卡住实例给明确答案（不再模糊 not-in-routing）。
- **MIN-13**：`securityGuard: armed` 改为**守卫能力自证**（recheck 可调），不再用对象存在性代理。
- **NIT-2/6**：pulses 死分支清理；`setReplyRoute` 对未注册实例 warn 不抛（实例退出后迟到 notify 是合法竞态，曾产生 unhandled rejection）。
- **NIT-1**（run-serve-child 委派块可读性壳）降级 deferred——纯可读性、缩进手术风险大于收益。
- 全量 4614 passed。

### feat(gateway): P0c ops 运维入口 — fleet spawn/promote/rollback/drain 产品面可达

- **MAJ-4 ops 生产可达**（评审：P0c-3/P0c-4 验收此前只在测试语境成立）：`FleetOps` 接入 gateway——`spawnRunInstance` 统一自举与版本化拉起（`buildRef:'self'` 走同构建，其余直指构建入口）；自举实例同登记 registry/fleet（roll-forward 闭环：spawn 新版本 → promote → drain 自举）。
- **REST 入口**（`/api/v1/fleet/*`，鉴权随上游闸）：`GET /fleet`（事实+期望快照）、`POST /fleet/spawn|promote|rollback|drain`（参数校验 fail-loud）。
- **MIN-4 config 播种**（Q3=A 落地）：`fleet.replicasPerVersion` 配置字段（Zod + HarnessConfig + toGatewayConfig 映射，顶层键分类护栏走 mapped）→ `RouteConfig` 播种；promote/rollback 仍为运行态。
- **验证**：`/api/v1/fleet/*` 薄壳单测 4（路由/校验/透传）+ 配置映射护栏绿 + 全量 4614。

### fix(gateway): P0c 评审 MAJ 修复批 — 回执路由 / control 分类 / 跨版本自救 / 存活闭环

- **MAJ-1 回执路由串台与泄漏**：回执 id（`ap-/ask-/ct-`）由进程内自增改 `randomUUID`（多实例同 id 碰撞 → A 的审批会批掉 B 的调用）；回执表终态即删（成败都删）；`unregister` 清该实例全部回执项。
- **MAJ-2 control 分类漏网**：`syncKnowledgeState` 入 fleet-wide fan-out（每实例一份 knowledge 准入快照，漏同步=旧快照 fail-open）；`contextHealth` 归最闲实例透传（曾 unrouteable 恒失败、静默退化磁盘扫描）；`syncKnowledgeState`/`askUserReply` 调用点统走 fleet（原直连 run-0 绕过路由）。
- **MAJ-3 跨版本自救被健康门卡死**：`/smoke` 为 v0.108.2 新增端点，旧构建 404 会被误判冒烟失败挡回滚（根需求「切回旧版本」失效）。`smoke()` 判 HTTP 状态；404 → `unavailable` 显式降级标记，健康门降级为 health+guard 判定并 warn（fail-loud, degrade explicitly）；`smoke()` 拒绝非 2xx。
- **MAJ-5 存活闭环**：`RemoteRunBackend` 新增 `onExit` 回调——实例退出即移出路由面（sticky/pulse/回执随 unregister 清，防 sticky 会话黑洞）；drain **开始**即疏散（sticky 迁走 + pulse 归属转移触发，§5.2）；draining 的 sticky 亲和改为失效（修订 §7.1 旧语义：drain=停止接一切新 run，否则排空永不收敛）；drain 重入改为继续等到 idle（原超时后重试假成功）。
- **MIN-1/8/14**：spawn 回填真实 port/pid（`InstanceBackend.info`）；探针类 fetchJson 带 30s 超时（`/runs` 长流不受限）；ops 状态迁移统一走 `registry.setState`（单一写路径）。
- **验证**：新增回归锚 4 个（contextHealth/syncKnowledgeState 路由、回执终态即删+注销清理、draining 疏散、smoke 跨版本降级）；全量测试套件绿。

### fix(gateway): 委派工具挂载回归 — 缺省默认开启被误当禁用（P0b S2）

- **症状**：P0b 进程拆分后 `delegate_dispatch/list/get/cancel` 从 agent 工具面消失（未显式声明 `delegation` 的 agent 全部丢委派能力）。
- **根因**：`run-serve-child.ts` 委派接线的外层守卫 `if (delegation !== undefined)` 直接读字段——把「未声明 = 缺省开启」（`registry-types.ts` AgentDelegationPolicy 明文：缺省默认具备委派能力，一律经 `effectiveDelegationPolicy()` 取生效值）当成「未声明 = 禁用」。P0b 前 gateway 侧 `wireDelegation` 判定正确（`effectiveDelegationPolicy(a.delegation).canDelegate`），S2 迁移时守卫语义换错。同型直接读字段点已全仓排查（仅此一处）。
- **验证**：smoke 报告 tools 明细新增工具名清单；e2e 新增回归锚「未声明 delegation 的 agent 必须挂 `delegate_dispatch`」；全量测试套件绿。

### test(gateway): P0c-4 验收演练 — 自救 + 多活（真进程 e2e）

- **自救演练**（§6 验收 1）：v-good 就位 → 故意起坏版本（入口存在但启动即炸的 fixture 构建）→ 起不来即 failed 终态、不入路由、**流量留旧版本**（新会话仍进 v-good）→ 修好过门 → promote → 新会话进 v-fixed → drain v-good（停机注销）。全链真进程。

### feat(gateway): P0c-3 健康门 + 版本化 spawn + 生命周期 ops

- **健康门**（§4.3，Q2 落地含冒烟）：probe 链 = health 可达 → `POST /smoke` 冒烟 → **守卫在位核查**（配置含 securityIntegrity 而实例报 `absent` 即拒——收口跨版本漂移闸 fail-open 缺口）。冒烟为独立通道（不是 run）：强制走一遍惰性装配热路径 + 逐 agent 工具面枚举 + no-LLM 应答（contextHealth），报告 `RunSmokeReport` 如实入 checks。

## v0.106.0 (2026-11-10)

### feat(plugin): distribution & deployment pipeline — dependency closure + octopi plugin install (P6-6)

A deployable plugin copy is **files + the runtime dependency closure** (Node
resolves `node_modules` next to the entry at import), so dependency
installation is part of deployment. `octopi plugin sync` installs runtime
dependencies in staging before the swap (`npm install --omit=dev`) or reuses
the deployed `node_modules` when the dependency set is unchanged (offline);
`--skip-install` preserves the existing closure instead of installing — it is
never silently dropped. `octopi plugin install <npm-spec>` opens the npm
distribution channel (registry/git/tarball): fetch, manifest verification,
loadability checks (entry resolves, engine range satisfied), dependency
install, atomic swap — the npm package carrying `octopi.plugin.json` is the
distribution unit (init scaffolds one; a marketplace can ride the same
channel later). `octopi plugin doctor` gained PLG009 (missing/mismatched
runtime dependencies are errors; Node-resolution aware so hoisted workspace
deps resolve; non-semver specs verified by presence only) and PLG010 (stale
sync scratch dirs — informational).

**Install-script consent is operator-side, never publisher-side**: installs
run with `--ignore-scripts` unless the CLI carries `--allow-scripts`; a
manifest `installScripts: true` is a requirement declaration, not a
permission — without consent deployment is refused (a skipped postinstall
would be a silently broken plugin). The fetch stage (`npm pack`) always
skips publisher scripts (argv builders are exported and test-pinned); npm
git-dependency preparation follows the local npm version's own script
policy. The channel carries no integrity pinning — install by pinned spec
and treat it as trusting the registry.

Incident lesson recorded (arch/plugin-system-v1.md P6-6): a delete-safety
check that used the deployment inventory (which excludes `node_modules`) is
the wrong predicate — deployment inventory and delete-safety answer different
questions. That operational mistake (52 packages removed) drove this
release's closure-first design.

- Verified: build/lint/full suite (432 files, 4506 tests)/arch-check-sync
  green; 41 tooling cases cover the argv security anchors (scripts never run
  without operator consent), staged install ordering (install before swap;
  a failing install leaves the previous deployment untouched), the
  unchanged-deps reuse fast path, skip-install closure preservation,
  PLG009/010 semantics (hoisting, non-semver specs, corrupt package.json),

## v0.105.3 (2026-11-10)

### feat(plugin): contribution instance registry + api.getContributionInstance (P6-3)

Factory-backed contributions (providers, channels) now register the runtime
instances the Host serves. **Birth = Host acceptance**: `record.acceptInstance`
runs after contract validation and records the factory product itself (plugin-
specific methods live only there; with `observability.llmRequestDump` the Host
routes through a decorator copy that forwards SPI calls to it — acceptance runs
before decoration so the copy's `dispose` forwarding closes the retirement
chain). The registry's "live" set matches what the Host routes to: rejected
factory products are never tracked, and a pre-built instance whose config
apply aborts before install is rolled back (`discardInstance` resurrects the
instance it superseded). Retirement has two idempotent triggers: physical (the
instance's `stop()`/`dispose()` runs — recorded on request regardless of
outcome; `dispose` is defined as a marker when the provider has none) and
logical (routing removal — hot-reload replace supersedes, provider removal /
config reset marks immediately; deferred disposal is only the physical
backstop, lookup stops returning at retirement). Re-accepting a retired
singleton revives its entry. Instances whose retirement cannot be tracked
(frozen/sealed) are never registered and never patched — the Host logs an
explicit warning and its contract validation stays the authority on broken
adapters.

Plugins reach their own live instance through the narrow lookup
`api.getContributionInstance(kind, id)` with exactly-one semantics: one live
instance is returned; otherwise a real error distinguishes never-instantiated /
retired / ambiguous multi-live (naming the instance labels) / not a
contribution of this plugin; unknown kinds and non-string ids are rejected at
runtime (the API is reachable from plain JS). This replaces module-closure
bridges — the weixin example's `weixin_pair` tool now queries the registry
instead of a shared `let adapter`. Cross-plugin lookup is deliberately outside
the v1 contract. Public docs updated in both languages.

### fix(gateway): provider teardown paths retire displaced instances

`resetRuntimeConfig` rebuilt the provider map with bare delete/overwrite —
displaced instances were neither disposed nor retired (a pre-existing resource
leak); they now go through `retireProvider` like `replaceProvider` /
`removeProvider`. `retireProvider` additionally marks logical retirement in
the plugin instance tables at routing removal, so lookups never hand out an
instance the Host no longer routes to during the 30-minute dispose grace
window.

  cover acceptance births and rollbacks (incl. the real
  `createProviderFromConfig` / `createChannelAdapterFromConfig` paths, the
  no-phantom-on-rejection invariant, and wire-dump dispose forwarding),
  physical + logical retirement, supersession and revival of singletons,
