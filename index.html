Octopi · Distribution

三种发行形态

同一套引擎，按受众与交付物切成三档。命名族 @octopi-agent/* + 套件 octopi-agent； 三档是消费面，开箱形态靠依赖一次装齐。

Product 侧

集成商两条路

① 进程内嵌入

只装 @octopi-agent/engine，调 AgentBuilder / Agent.run()，自接消息通道。不拉 HTTP 面。

② 再装 Gateway

@octopi-agent/gateway 提供 HTTP/WS + ChannelAdapter；业务总线/IM 挂在它上面。E7：跨进程要换 Session Lease。

与「开箱」的关系 Engine 用户可以不装 Gateway/WebUI；Product 用户会自动带上这两个包。拆包是为了按需安装，不是为了让人自己拼版本。

安装与入口

# 仅运行时（可选：+ gateway + webui）
npm install @octopi-agent/engine
npm install @octopi-agent/gateway # 需要 HTTP/WS 时
npm install @octopi-agent/webui # 需要控制台 UI 时
import { AgentBuilder, Agent } from '@octopi-agent/engine'

为什么套件包是 octopi-agent，而不是 @octopi-agent

npm i @octopi-agent 装不了 · 裸 scope
npm i octopi-agent 推荐 · 套件入口
@octopi-agent/suite 也可 · 多一层
octopi-cli 范围过窄

# 或

Web 交付约束 @octopi-agent/webui 必须发预构建 web/dist，而不是源码 + 用户装 Vite。否则「开箱」不成立。

命名（承接 npm 调研）

为什么用 @octopi-agent，而不是 @octopi

registry 上的 octopi 是 2019 年 express-php 胶水框架。scope 必须不是 @octopi，否则会被读成它的子包。

npm i octopi 撞名 · 废弃包
@octopi/engine 易读成子包
@octopi-agent/* + octopi-agent 推荐 · 独立品牌族
原则 @octopi-agent 是独立 scope（octopi-agent 项目），不是 octopi 的下级。 「总的叫 octopi-agent」= 套件包 octopi-agent；零件在 @octopi-agent/*。 文档写全名；命令行写 octopi。
演进路径
PHASE 1 · 现在

单包 · 五个消费面

仍是一个 npm 包，用 exports 表达 core / engine / gateway / web / cli 胶水。先把边界与命名写进文档，避免过早拆包。

PHASE 2 · 拆包

monorepo packages/*

按拓扑拆成 @octopi-agent/core → engine → gateway / webui，套件 octopi-agent 用 dependencies 装齐三者。

PHASE 3 · 多端壳

桌面 / 移动

新壳包复用 gateway + web + engine；发行走安装包/商店。npm 主路径仍是 suite。

切分时的关键决策
01
Gateway / WebUI 独立成包，套件负责「一起装上」 集成商按需只装 engine 或 +gateway；产品用户 npm i octopi-agent 一次装齐。开箱 = 依赖收拢，不是巨型单包。
02
scope 用 @octopi-agent，套件用无 scope octopi-agent 避开废弃包 octopi 与 @octopi 子包误读；裸 scope 装不了，套件必须有独立包名。
03
WebUI 必须预构建 @octopi-agent/webui 发 web/dist 静态产物；源码 + Vite 不是产品交付。
04
Core 保持零业务策略 Session/Memory/Gateway/UI 不进 Core，否则三档塌成一档。
05
先 exports，后物理拆包 API 稳定前拆包 = 五处版本对齐。Phase 1 文档定义边界即可。
推荐包名族：@octopi-agent/core · @octopi-agent/engine · @octopi-agent/gateway · @octopi-agent/webui · 套件 octopi-agent（bin: octopi）。 约束不变：Node ≥ 24 · 单进程 v1 · Core 不依赖 Harness。
